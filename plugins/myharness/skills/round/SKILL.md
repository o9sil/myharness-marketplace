# 라운드 진행 절차

문서 위치는 아래를 기본으로 한다. 프로젝트 CLAUDE.md가 다른 위치를 정하면 그것을 따른다.
- `docs/ROADMAP.md`: 라운드 계획과 상태. 지금 어느 라운드인지 여기서 확인한다.
- `docs/SSOT.md`: 진실의 원천. 지금 서비스의 API, 데이터 모델, 규칙.
- `docs/roundNN/`: 라운드마다 `spec.md` → `plan.md` → `review.md`.

## 1. 시작
1. ROADMAP에서 이번 라운드(NN)와 목표를 확인한다. ROADMAP이 없으면 사람에게 이번 라운드 목표를 묻는다.
2. `docs/roundNN/spec.md`를 쓴다: 목표, 요구사항, 범위 밖.
3. `docs/roundNN/plan.md`를 쓴다: 바꿀 파일과 순서를 번호 목록으로.
4. spec과 plan을 사람에게 보여주고 확인받은 뒤 구현한다.

## 2. 구현
- plan 순서대로 구현하고 테스트를 더한다.
- 프로젝트 CLAUDE.md의 코드 규칙과 실행 규칙을 따른다.
- Hook에 막힌 작업은 다른 명령으로 우회하지 말고 멈춰서 사람에게 보고한다.

## 3. 검증과 정리
1. verifier 에이전트로 spec 기준 검증을 받는다. 문제가 나오면 고치고 다시 검증한다.
2. cleaner 에이전트로 죽은 코드와 어긋난 문서를 정리한다.

## 4. 마무리 (종료 조건)
아래를 모두 지킨 뒤에만 라운드가 끝났다고 보고한다. 하나라도 안 되면 무엇이 남았는지 보고한다.
1. `docs/roundNN/spec.md` · `plan.md` · `review.md`가 지금 코드와 맞는다.
2. `docs/SSOT.md`를 지금 코드 기준으로 고쳤다. (현재 라운드, API 목록, 데이터 모델)
3. cleaner 결과와 verifier 결과를 `review.md`에 적었다.
4. 프로젝트의 테스트 · 린트 명령이 통과한다.
5. `docs/ROADMAP.md`에서 이번 라운드를 완료로 표시했다.

## review.md 형식
- 검증 결과 (verifier): 통과 · 문제
- 정리 결과 (cleaner): 지운 것 · 고친 것 · 사람이 판단할 것
- 결정: 이번 라운드에서 미룬 것과 이유
- 종료 조건 점검: 1~5번 각각 지킴 / 안 지킴
